# How to Use Junie Conversation Viewer

## Overview

Junie Conversation Viewer is a desktop application for reading and exploring Conversation logs generated by the Junie agent. A **Conversation** is the complete exchange within a single Junie **Session**, stored as an `events.jsonl` file. Each line in the file is an **Event** that the viewer parses into human-readable **Messages**.

## Selecting a Session

- On launch, the viewer scans `~/.junie/sessions/` for available Sessions.
- Select a Session from the session picker button in the top chrome.
- To change the Junie home path, open **Settings** and update the path.
- If no Sessions appear, verify that `~/.junie/sessions/` contains session directories with `events.jsonl` files.

## Reading the Conversation

- **Human Messages** appear on the left side of the screen (33% width) with a distinct accent rail.
- **Junie Messages** appear on the right side (90% width) with their own accent rail.
- Messages are grouped into **Turns** — each Turn begins when Junie starts responding to a Human prompt.
- Each Message has a **Message Kind** marker (coloured dot + label) indicating its type: Text, Thought, Tool, Patch, Terminal, Markdown, Error, Warning, Test, MCP, SubAgent, Question, Choice, System, Cancelled, Status, or Unsupported.
- **Sub-agent** markers show when Junie delegates work to a specialised sub-agent (e.g., `android-qa-agent`).
- **Error/failure Messages** (including Task Failed) render as prominent error blocks.

## Search

- Type a **Search Query** in the search field (or press Cmd+F / Ctrl+F).
- Search is case-insensitive substring matching across all visible Message content.
- The **match count** displays how many matches were found and your current position.
- Use the **▲/▼ navigation buttons** to jump between matches.
- **Search highlighting**: matching text is highlighted in the Conversation. The current match has a distinct highlight colour.
- Search highlighting works in plain text, code blocks, terminal output, and other rendered content.

## Filters

Filters control which Message Kinds are visible. Toggle filters using the pill-shaped chips in the top chrome.

Available filter categories:
- **Human** — Human prompt Messages.
- **Junie** — Junie text and markdown responses.
- **Thoughts** — Junie's internal reasoning blocks (collapsed by default).
- **Tools** — Tool calls, Structured Output, MCP invocations, and Sub-agent blocks.
- **Patches** — Code diffs and patches created by Junie.
- **Terminal** — Terminal command output and Test Run results.

Some Message Kinds are **always shown** regardless of filter state: Errors, Warnings, Questions, Choices, System Messages, Cancelled, Status, and Unsupported events.

## Copying and Text Selection

- **Select partial text**: Click and drag to select text within any Message. Most content is selectable.
- **Copy buttons**: Rich content blocks (code, terminal, diff, tool calls) include a copy button for copying the full block content.
- Copied content is placed on the clipboard as **plain text**.

## Rich Content Blocks

The viewer renders several types of rich content:

- **Thought** — Junie's reasoning, collapsed by default. Click to expand.
- **Tool Call** — Tool invocations shown as collapsible JSON blocks.
- **Code** — Syntax-highlighted code blocks with a copy button.
- **Patch/Diff** — Code changes with added/removed line colouring and hunk headers.
- **Terminal Output** — Command and output display with command highlighting.
- **Structured Output** — Formatted data from tools and MCP calls.
- **Error/Warning/Task Failed** — Prominent error blocks. Task Failed events show failure details when available.
- **Markdown** — Rendered markdown content from the agent.

Rich content blocks are **collapsible** — click the header to expand or collapse. Some blocks (like Thoughts and Tool Calls) start collapsed by default.

## Live Session Tracking

When a Session is selected, the viewer automatically watches the `events.jsonl` file for changes.

- Updates are checked on a regular polling interval.
- New Events appended to the file appear as new Messages in the Conversation.
- **Scroll preservation**: If you are scrolled up reading earlier content, the view stays in place. If you are at the bottom, new Messages auto-scroll into view.
- **Partial writes**: If Junie is mid-write, there may be a brief delay before the partial line is complete and parseable.
- **File deletion/truncation**: If the file is deleted or truncated, the viewer reloads from the current file state.

## Theme

Three theme modes are available:
- **Light** — Light background with dark text.
- **Dark** — Dark background with light text.
- **System** — Follows your operating system's appearance setting.

Change the theme in the **Settings** dialog.

## Troubleshooting

- **No Sessions found**: Verify that `~/.junie/sessions/` exists and contains session directories with `events.jsonl` files. Check the Junie home path in Settings.
- **Unsupported Events**: Events the viewer does not yet recognise are shown as "Unsupported event" cards. They are parsed safely and no data is lost.
- **Conversation does not update live**: Ensure the Session's `events.jsonl` file is being written to. Check application logs in `~/.junieviewer/logs/`.
- **Search does not find expected text**: Search matches visible content only. Check that the relevant filter is enabled. Search is case-insensitive but matches substrings only.
- **Very large blocks**: Large code blocks, diffs, or terminal output may take a moment to render. Collapsing them improves scroll performance.
- **Logs**: Application logs are stored in `~/.junieviewer/logs/` with rolling file rotation.

## Known Limitations

- **Platform verification**: Only macOS has been fully verified. Windows and Linux are expected to work but have not been HITL-verified.
- **Syntax highlighting theme**: Code block syntax highlighting does not yet follow the Light/Dark theme selection.
- **Markdown search highlighting**: Search highlighting within rendered Markdown content may not highlight all matches.
- **Side-by-side diff view**: Not yet implemented; diffs render in unified format.
